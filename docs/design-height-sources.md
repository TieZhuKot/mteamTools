# 设计：扩充女优身高数据源 + 名字治理

> 状态：**已实施（1.8.7，2026-11-20）**，已通过五套件测试与构建校验。
> 目标：提高身高覆盖率（补更多名字），不是替换现有数据。

## 1. 现状

已有 4 个源，合并后 `build/actress-height.json` 为 8191 条；加入 javdatabase 后为 8408 条：

| 源 | 脚本 | 说明 |
|---|---|---|
| DMM/FANZA 官方 API | `fetch-actress-height.mjs` | 官方，质量最高，607 页 |
| av-joyu-db.com | `fetch-avjoyudb-height.mjs` | 按身高分类页爬详情 |
| warashi-asian-pornstars.fr | `fetch-warashi-height.mjs` | 98 页 / 3524 人 |
| Wikidata SPARQL | `fetch-wikidata-height.mjs` | 结构化，覆盖偏老牌 |

数据审计结果：身高值全在 133–190，无异常值；可疑名字只有 11 个，
其中真正会撞词的短拉丁名只有 `AI` 和 `AN`（`AI` 已在 1.8.5 从匹配中排除）。

## 2. 新源选型

### 选定：javdatabase.com

验证过的事实（2026-11-20，经 `http://127.0.0.1:21578` 代理）：

- 列表页 `https://www.javdatabase.com/idols/?_height=160.00,160.00` 按身高筛选，
  每个身高段 2–3 页，分页链接形如 `/idols/page/2/`。
- **列表页只有罗马字名**，没有日文名。
- 详情页（如 `/idols/mai-hirukawa/`）同时有：
  - `JP: 比留川マイ` —— 日文名，正是 M-Team 标题使用的名字形态
  - `Height: 160 cm` —— 身高
- 开源项目 xbvr 已验证过相同字段（规则：`div > b:contains("Height:") + a`）。
- 站点对部分地区有访问限制，本机必须走代理；WebFetch 出口被判为英/澳/法时被拦。

**结论**：可行，但需要「身高筛选页 → idol 链接 → 详情页」两级抓取，不能只抓列表。

### 淘汰的候选

| 候选 | 淘汰原因 |
|---|---|
| 日文维基百科 | AV 女优条目有限，新源增量小；SPARQL 直连在本机超时 |
| 百度百科 / 搜狗百科 | 非结构化、反爬强，批量成本高 |
| 片商官网 / Grokipedia | 各家格式不同；后者数据源头还是前面几个，无增量 |

## 3. 采集方案

新脚本 `tools/fetch-javdatabase-height.mjs`：

1. **身高段遍历**：133–190 每个整数，请求 `/idols/?_height=N.00,N.00`。
   也可以只抓「缺失名字」优先的身高段，避免重复抓已知名字。
2. **分页收集**：从筛选页提取 `/idols/<slug>/` 链接；遇到 `rel=next` 继续翻页。
3. **详情抓取**：每个 slug 请求详情页，提取 `JP:` 日文名和 `Height:` 数字。
4. **缓存**：`build/cache/javdatabase-links.json`（链接表）+ `build/cache/javdatabase-raw.jsonl`（明细），
   断点续传，与现有脚本风格一致。
5. **代理**：命令行 `--proxy http://127.0.0.1:21578`，默认不启用（可直连时不用代理）。
6. **限速**：默认 `--delay 400`，可重试，失败记录不覆盖已有缓存。
7. **产出**：`build/javdatabase-cache.json`，结构 `{ "比留川マイ": 160, ... }`。

## 4. 合并策略

更新 `tools/merge-height-data.mjs`，优先级（同名冲突时前者胜）：

1. `build/actress-height.json`（现有，最高优先级，绝不覆盖）
2. **`build/javdatabase-cache.json`（新源，插在第二位）**
3. `build/avjoyudb-cache.json`
4. `build/cache/warashi-height.jsonl`

规则：只补**缺失的名字**，不覆盖已有身高；新源带来的名字写入前做归一化
（全角→半角、去空格/括号）后与现有名字比对，避免重复条目。

## 5. 名字治理

- `IGNORED_NAMES` 增加 `AN`（与 `AI` 一样，两字母极易撞词）。
- 新增源带来的名字做一次审计：单字、两字母、含数字的名字单独列出来人工过目，
  不自动加入忽略名单（避免误杀真名）。

## 6. 测试计划（TDD，先红后绿）

| 测试 | 覆盖 |

| 产物冒烟 | 新数据集构建成功，条目数增加，身高范围仍合法 |

## 7. 风险与降级

- **站点改版 / 地区限制**：解析失败时脚本保留旧缓存，不覆盖；报错后允许 `--merge-only` 用旧缓存合并。
- **日文名与 M-Team 不一致**：新源补的名字可能仍然匹配不上标题；这是增量尝试，不保证每条都生效。
- **代理依赖**：代理未启动时会失败，脚本明确提示，不静默跳过。

## 8. 范围边界

- 不改运行时脚本的匹配核心（`src/core.mjs` 只在忽略名单上做最小改动）。
- 不发运行时网络请求——新脚本是**离线构建工具**，不影响用户浏览器行为。
- 不覆盖已有数据条目。
